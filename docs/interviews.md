<section class="runbook-step" id="step-1">
  <header class="step-header">
    <span class="step-number">1</span>
    <div><p class="step-type">Before recording · 5–10 minutes</p><h2>Prepare the conversation.</h2></div>
  </header>
  <p class="step-intro">Do these six things before anyone starts answering. If one is unknown, name it and continue. The agent can track it as an open question.</p>

  <div class="preflight-list">
    <label><input type="checkbox"> <span><strong>Recording permission</strong> Everyone knows the session will be recorded and transcribed.</span></label>
    <label><input type="checkbox"> <span><strong>People and roles</strong> Each speaker has stated their name, role, and what they can approve.</span></label>
    <label><input type="checkbox"> <span><strong>Private material</strong> Everyone knows to flag anything that must not become public.</span></label>
    <label><input type="checkbox"> <span><strong>Purpose</strong> You can say what this conversation should clarify or unlock.</span></label>
    <label><input type="checkbox"> <span><strong>Known evidence</strong> Current pages, documents, links, and assets are available if they already exist.</span></label>
    <label><input type="checkbox"> <span><strong>Private storage</strong> You know where the recording and transcript will be saved.</span></label>
  </div>

  <div class="facilitator-rule">
    <strong>The interview rhythm</strong>
    <ol>
      <li>Ask the main question.</li>
      <li>Listen without filling the silence.</li>
      <li>Use a probe only when something important is missing.</li>
      <li>Say what you heard and let the person correct it.</li>
      <li>Move on when the completion test is met or the gap is recorded.</li>
    </ol>
  </div>

  <div class="step-actions"><label class="milestone-check"><input type="checkbox" data-progress-item="prepare"> <span><strong>Ready to continue</strong> The room, recording, roles, and privacy expectations are clear.</span></label>
  <a class="continue-link" href="#step-2">Continue to project launch <span aria-hidden="true">↓</span></a></div>
</section>

<section class="runbook-step" id="step-2">
  <header class="step-header">
    <span class="step-number">2</span>
    <div><p class="step-type">Project launch · 15–25 minutes</p><h2>Establish what project you are doing.</h2></div>
  </header>

  <div class="read-aloud">
    <span>Read this aloud</span>
    <p>We are creating source material for your website. I will ask you to describe the church in your own words and explain how things work today. Hopes and recommendations are welcome, but we will label them separately. If something is uncertain, say so. We will create a follow-up question rather than fill the gap. Nothing becomes approved public copy until the right person reviews it.</p>
  </div>

  <div class="question-sequence">
    <p class="sequence-label">Ask in this order</p>
    <ol>
      <li><span>01</span><p>What is the church’s name, and who is the primary contact for this project?</p></li>
      <li><span>02</span><p>Are we creating a new site, redesigning the whole site, improving one area, or still deciding?</p></li>
      <li><span>03</span><p>Why is this project happening now? What should become easier or clearer because of it?</p></li>
      <li><span>04</span><p>What already exists: a website, domain, documents, brand files, photography, analytics, or connected systems?</p></li>
      <li><span>05</span><p>Who knows the church well enough to help, and who approves facts, theology, design, technology, and launch?</p></li>
      <li><span>06</span><p>What constraints are already known: timing, budget, platform, staffing, privacy, or access?</p></li>
      <li><span>07</span><p>What is the next concrete action after this conversation, who owns it, and what should it produce?</p></li>
    </ol>
  </div>

  <details class="probe-drawer">
    <summary>Only if this is a redesign</summary>
    <ul>
      <li>Which current pages or features are valuable and must be preserved?</li>
      <li>What do visitors repeatedly struggle to find?</li>
      <li>What is outdated, duplicated, inaccurate, or difficult to maintain?</li>
      <li>Are there URLs, downloads, archives, integrations, or search rankings that must be protected?</li>
      <li>What do analytics, search queries, or form submissions reveal?</li>
    </ul>
  </details>

  <div class="done-when"><strong>Move on when</strong><p>The project type, reason, primary contact, likely approvers, known evidence, major constraints, and next action are known or explicitly marked unknown.</p></div>
  <div class="step-actions"><label class="milestone-check"><input type="checkbox" data-progress-item="launch"> <span><strong>Project launch captured</strong> We can explain the project and name its next action.</span></label>
  <a class="continue-link" href="#step-3">Continue to Session A <span aria-hidden="true">↓</span></a></div>
</section>

<section class="runbook-step" id="step-3">
  <header class="step-header">
    <span class="step-number">3</span>
    <div><p class="step-type">Session A · 75–90 minutes</p><h2>Understand who the church is and who the site serves.</h2></div>
  </header>
  <p class="step-intro">Work through these modules in order. Ask the first question in each module, listen, then use the remaining questions only to complete what is missing.</p>

  <details class="question-module" open>
    <summary><span>3A</span><div><strong>Audience and outcomes</strong><small>Who needs the site and what should they be able to do?</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> Who most needs this website, and what do they need from it?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>When newcomer and member needs compete, who takes priority?</li><li>What kinds of first-time visitors do you commonly receive or hope to serve?</li><li>What languages, ages, abilities, family situations, or community realities matter?</li><li>What are the two or three most important visitor actions?</li><li>What should the website deliberately not try to do?</li></ul></div><div><h3>Complete when</h3><p>Priority audiences, their key questions, their main next steps, and the site’s limits are clear enough to guide the sitemap.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>3B</span><div><strong>Identity in plain language</strong><small>How an outsider should understand this church.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> If someone asked, “What kind of church is this?” how would you answer without insider language?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>What makes this congregation meaningfully itself?</li><li>What should a newcomer understand within ten seconds?</li><li>What do people often misunderstand about the church?</li><li>What do regular attenders value most?</li><li>Which three words should and should not describe the website experience?</li></ul></div><div><h3>Complete when</h3><p>You have a specific, understandable description that does not rely on generic promises or unexplained church language.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>3C</span><div><strong>Mission, vision, and values</strong><small>Approved language and evidence of what it means.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> What is the church’s approved mission statement, and what does it mean in ordinary language?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>What is the church seeking to become or accomplish?</li><li>Which values guide decisions and relationships?</li><li>What is one real example of each value in practice?</li><li>Which statements are approved, informal, or under review?</li></ul></div><div><h3>Complete when</h3><p>Exact approved statements are separated from explanations, examples, and aspirations.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>3D</span><div><strong>Story and present season</strong><small>The history that helps a visitor understand today.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> Why was the church started, and which moments most shaped what it is today?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Which details matter to long-time members? Which help newcomers?</li><li>How would you describe the present season?</li><li>Which parts require careful or private handling?</li><li>What historical documents or photographs exist, and may they be published?</li></ul></div><div><h3>Complete when</h3><p>The useful public story is separated from internal, uncertain, or sensitive history.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>3E</span><div><strong>Beliefs and ministry philosophy</strong><small>What must be stated accurately and approved.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> Is there an approved statement of faith, and which version is authoritative?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Is the church part of a denomination, network, or tradition?</li><li>Which beliefs are essential for a visitor to understand?</li><li>Which issues require exact approved wording?</li><li>How do these beliefs shape worship, discipleship, membership, baptism, communion, leadership, care, and mission?</li><li>Who approves summaries or edits?</li></ul></div><div><h3>Complete when</h3><p>The authoritative source, required public depth, affiliation language, and theology approver are named. Missing doctrine remains an open question.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>3F</span><div><strong>Voice and language</strong><small>How the church should sound to an outsider.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> How should the church sound when it speaks online?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Should copy use “we,” the church name, or both?</li><li>Which church terms matter, and which need explanation?</li><li>What phrases feel genuinely characteristic?</li><li>What clichés, tones, or phrases should be avoided?</li><li>How should scripture be quoted, and which current materials model the voice well?</li></ul></div><div><h3>Complete when</h3><p>A writer can distinguish authentic church language from generic church copy and knows which sources to follow.</p></div></div>
    </div>
  </details>

  <div class="session-close">
    <strong>Close Session A</strong>
    <p>Ask: “What important part of who this church is have we not discussed?” Then name any documents, approvals, or people still needed.</p>
  </div>
  <div class="done-when"><strong>Stop here when</strong><p>You can explain the priority audience, plain-language identity, mission, beliefs source, story boundaries, and voice. Anything unresolved is recorded for follow-up.</p></div>
  <div class="step-actions"><label class="milestone-check"><input type="checkbox" data-progress-item="identity"> <span><strong>Session A captured</strong> The church’s identity and audience are clear enough to structure.</span></label>
  <a class="continue-link" href="#step-4">Continue to Session B <span aria-hidden="true">↓</span></a></div>
</section>

<section class="runbook-step" id="step-4">
  <header class="step-header">
    <span class="step-number">4</span>
    <div><p class="step-type">Session B · 75–90 minutes</p><h2>Walk through the visitor experience and the church’s next steps.</h2></div>
  </header>
  <p class="step-intro">Start with a real Sunday journey. Concrete narration produces better website material than asking what a welcome page should say.</p>

  <details class="question-module" open>
    <summary><span>4A</span><div><strong>Service facts</strong><small>Exact details a visitor needs before leaving home.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> For each service or campus, what is its public name, day, time, exact address, and correct entrance?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Is it in person, online, or both?</li><li>Does the schedule change by season?</li><li>What style, language, or congregation does it serve?</li><li>How long does it normally last?</li><li>Where is the authoritative schedule, and who updates the website?</li></ul></div><div><h3>Complete when</h3><p>Every service has verified public details, a source of truth, and an update owner.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>4B</span><div><strong>First visit, beginning to end</strong><small>What someone will see, do, and need to know.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> Imagine I am arriving for the first time. Talk me through the visit from the road to the moment I leave.</p>
      <div class="module-columns"><div><h3>Follow the journey</h3><ul><li>How do I find parking and the right entrance?</li><li>Who greets me, and what happens next?</li><li>What happens during the service, in order?</li><li>What is the music style, usual clothing, and service length?</li><li>Will I be asked to stand, speak, give, complete a card, or identify myself?</li><li>What accessibility support is available?</li><li>What happens after the service, and what is the simplest next step?</li></ul></div><div><h3>Complete when</h3><p>A newcomer can picture the whole visit, including moments of uncertainty, accessibility, expectations, and the next step afterward.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>4C</span><div><strong>Children, youth, and family safety</strong><small>Open when children or youth programs are part of the visit.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> What should a parent or guardian know before bringing a child for the first time?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Which ages or grades are served during each service?</li><li>Where and when does check-in happen?</li><li>What may be said publicly about screening and safety?</li><li>What allergy, accessibility, pickup, or custody details matter?</li><li>What information or photography must remain private?</li><li>Who answers family questions?</li></ul></div><div><h3>Complete when</h3><p>Families know what to expect without publishing sensitive security or child information.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>4D</span><div><strong>Ministries and groups</strong><small>Repeat the same structure for each significant ministry.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> What is this ministry for, what actually happens, and what should an interested person do next?</p>
      <div class="module-columns"><div><h3>For each ministry</h3><ul><li>Name, audience, and purpose</li><li>Activity, schedule, and location</li><li>Current, seasonal, or inactive status</li><li>Next action, cost, prerequisite, capacity, or restriction</li><li>Leader, approved public contact, and detail owner</li><li>Whether it needs a page or only a listing</li></ul></div><div><h3>Complete when</h3><p>Every included ministry has a clear audience, current status, useful description, next action, and owner.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>4E</span><div><strong>Next steps and belonging</strong><small>How a person moves from interest to connection.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> After someone visits, how do they move toward meaningful connection?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>How do people learn about membership, baptism, groups, classes, serving, care, or giving?</li><li>Which are formal processes and which are informal invitations?</li><li>Is there a recommended sequence?</li><li>Which steps require a form or outside system?</li><li>Who follows up, and what response expectation is honest?</li></ul></div><div><h3>Complete when</h3><p>The site can offer a small number of real next steps, each with an owner and accurate expectation.</p></div></div>
    </div>
  </details>

  <details class="question-module">
    <summary><span>4F</span><div><strong>Contact, care, and forms</strong><small>Where messages go and what must remain private.</small></div></summary>
    <div class="module-body">
      <p class="ask-first"><span>Ask first</span> What contact information is public, and which kinds of requests need their own path?</p>
      <div class="module-columns"><div><h3>Fill the gaps</h3><ul><li>Confirm address, phone, email, office hours, and entrance details.</li><li>Separate general contact, prayer, care, counseling, benevolence, facility, wedding, funeral, school, or media requests as needed.</li><li>For each form, who receives it and who provides backup?</li><li>What response time is realistic?</li><li>What sensitive information should a form never request?</li><li>What confirmation, consent, privacy, or retention notice is needed?</li></ul></div><div><h3>Complete when</h3><p>Every public contact route reaches a named owner, protects sensitive information, and sets an honest expectation.</p></div></div>
    </div>
  </details>

  <div class="session-close">
    <strong>Close Session B</strong>
    <p>Ask: “What would a first-time visitor still worry about or struggle to find?” Then identify which specialist modules below still need a person, document, or decision.</p>
  </div>
  <div class="done-when"><strong>Stop here when</strong><p>Service facts, the first-visit journey, family needs, ministries, next steps, and contact routes are complete enough to plan visitor pages. Unfinished specialist topics have owners.</p></div>
  <div class="step-actions"><label class="milestone-check"><input type="checkbox" data-progress-item="experience"> <span><strong>Session B captured</strong> A visitor’s practical journey and next steps are clear.</span></label>
  <a class="continue-link" href="#step-5">Open specialist modules <span aria-hidden="true">↓</span></a></div>
</section>

<section class="runbook-step" id="step-5">
  <header class="step-header">
    <span class="step-number">5</span>
    <div><p class="step-type">Follow-ups · Use only what applies</p><h2>Fill the operational gaps that affect the website.</h2></div>
  </header>
  <p class="step-intro">Do not force all six modules into Session B. Let the agent identify which ones are incomplete, then invite the person who can answer that topic accurately.</p>

  <details class="question-module compact-module">
    <summary><span>5A</span><div><strong>Leadership and governance</strong><small>People, roles, biographies, and public explanation.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> Which leaders should appear publicly, and what information is approved for each?</p><ul><li>Confirm name, title, role, biography, photograph, and public contact details.</li><li>Decide how much governance should be explained online.</li><li>Flag vacant or changing roles.</li><li>Name the person who approves biographies and titles.</li></ul><div class="done-when"><strong>Complete when</strong><p>Every public leader entry is approved, current, and owned.</p></div></div>
  </details>

  <details class="question-module compact-module">
    <summary><span>5B</span><div><strong>Sermons, livestream, and media</strong><small>Source, organization, publishing, and restrictions.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> Where are sermons and livestreams hosted, and which source is authoritative?</p><ul><li>Choose useful history and organization: date, series, speaker, scripture, or topic.</li><li>Confirm transcripts, notes, podcasts, downloads, and Church Online needs.</li><li>Record music licensing, privacy, and child-photo restrictions.</li><li>Name who publishes and checks each new item.</li></ul><div class="done-when"><strong>Complete when</strong><p>The source, display rules, restrictions, and publishing owner are clear.</p></div></div>
  </details>

  <details class="question-module compact-module">
    <summary><span>5C</span><div><strong>Events and seasonal content</strong><small>Calendars, registration, landing pages, and expiration.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> Where is the official calendar, and which events belong on the public website?</p><ul><li>Separate public and internal events.</li><li>Identify feeds, embeds, registration, payments, waivers, and capacity limits.</li><li>Decide which recurring events are ministries and which seasonal events need landing pages.</li><li>Name who creates, approves, publishes, and removes event content.</li></ul><div class="done-when"><strong>Complete when</strong><p>Events have a source of truth, publishing rule, and removal owner.</p></div></div>
  </details>

  <details class="question-module compact-module">
    <summary><span>5D</span><div><strong>Giving and stewardship</strong><small>Provider, explanation, verification, and ownership.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> Which giving link is authoritative, and what should people understand before using it?</p><ul><li>Confirm funds, recurring gifts, fees, tax statements, and other practical details.</li><li>Capture how the church explains the purpose and impact of giving.</li><li>Verify permission for any stories or examples.</li><li>Decide whether volunteering, in-kind gifts, legacy giving, or facility use belongs here.</li><li>Name the page owner and verifier.</li></ul><div class="done-when"><strong>Complete when</strong><p>The giving path is accurate, appropriate, approved, and owned.</p></div></div>
  </details>

  <details class="question-module compact-module">
    <summary><span>5E</span><div><strong>Brand, design, and assets</strong><small>What exists, what may change, and what may be published.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> What visual work already exists, and which parts are mandatory, preferred, outdated, or open to change?</p><ul><li>Review logos, colors, fonts, templates, signage, print pieces, and guidelines.</li><li>Ask for two or three liked and disliked references, with the specific reason for each.</li><li>Identify the visual qualities that truthfully fit the church.</li><li>Inventory real photography and video, ownership, and publication permission.</li><li>Record accessibility needs, visual clichés to avoid, and the design approver.</li></ul><div class="done-when"><strong>Complete when</strong><p>The agent knows the existing constraints, usable assets, desired qualities, anti-references, permissions, and approver.</p></div></div>
  </details>

  <details class="question-module compact-module">
    <summary><span>5F</span><div><strong>Technology, integrations, and maintenance</strong><small>Accounts, systems, security, updates, and long-term ownership.</small></div></summary>
    <div class="module-body"><p class="ask-first"><span>Ask first</span> Who owns the website and connected accounts today, and who will maintain them after launch?</p><ul><li>Confirm platform, host, domain, DNS, administrators, and backup access.</li><li>List church management, forms, giving, events, sermons, livestream, email, text, maps, analytics, and CRM integrations.</li><li>Name the source of truth for each data type.</li><li>Record budget, staff skill, procurement, privacy, security, backup, monitoring, and update constraints.</li><li>Assign owners for service facts, staff, ministries, events, sermons, forms, giving, and seasonal pages.</li><li>Define how changes are requested and what review rhythm is realistic.</li></ul><div class="done-when"><strong>Complete when</strong><p>Every critical system and changing content type has an owner, backup, update method, and known constraint.</p></div></div>
  </details>

  <div class="decision-rule">
    <strong>If time runs out</strong>
    <p>Finish the current question, ask the closing questions below, and stop. Do not rush through the remaining modules. The transcript should produce the next focused interview.</p>
  </div>
  <div class="step-actions"><label class="milestone-check"><input type="checkbox" data-progress-item="operations"> <span><strong>Follow-ups routed</strong> Every relevant specialist module is complete or assigned to the right person.</span></label>
  <a class="continue-link" href="#step-6">Process the interview <span aria-hidden="true">↓</span></a></div>
</section>

<section class="runbook-step" id="step-6">
  <header class="step-header">
    <span class="step-number">6</span>
    <div><p class="step-type">After each recording · 15 minutes</p><h2>Close cleanly and hand the evidence to the agent.</h2></div>
  </header>

  <div class="question-sequence closing-questions">
    <p class="sequence-label">Ask before stopping the recording</p>
    <ol>
      <li><span>01</span><p>What important subject have we not discussed?</p></li>
      <li><span>02</span><p>What did you expect me to ask that I did not?</p></li>

  (() => {
    const storageKey = "church-blueprint-interview-progress-v1";
    const items = Array.from(document.querySelectorAll("[data-progress-item]"));
    const meter = document.querySelector("[data-interview-progress]");
    const label = document.querySelector("[data-progress-label]");
    const reset = document.querySelector("[data-reset-progress]");
    const runbookLinks = Array.from(document.querySelectorAll("[data-runbook-link]"));
    const runbookSteps = runbookLinks.map((link) => document.querySelector(link.hash)).filter(Boolean);

    const readSaved = () => {
      try { return JSON.parse(localStorage.getItem(storageKey) || "[]"); }
      catch { return []; }
    };

    const update = () => {
      const completed = items.filter((item) => item.checked);
      items.forEach((item) => item.closest(".milestone-check")?.classList.toggle("is-complete", item.checked));
      if (meter) { meter.max = items.length; meter.value = completed.length; }
      if (label) label.textContent = `${completed.length} of ${items.length}`;
      try { localStorage.setItem(storageKey, JSON.stringify(completed.map((item) => item.dataset.progressItem))); }
      catch { /* Progress persistence is optional. */ }
    };

    const saved = readSaved();
    items.forEach((item) => {
      item.checked = saved.includes(item.dataset.progressItem);
      item.addEventListener("change", update);
    });

    reset?.addEventListener("click", () => {
      items.forEach((item) => { item.checked = false; });
      document.querySelectorAll(".preflight-list input").forEach((item) => { item.checked = false; });
      update();
    });

    if ("IntersectionObserver" in window) {
      const observer = new IntersectionObserver((entries) => {
        const visible = entries.filter((entry) => entry.isIntersecting).sort((a, b) => a.boundingClientRect.top - b.boundingClientRect.top)[0];
        if (!visible) return;
        runbookLinks.forEach((link) => {
          if (link.hash === `#${visible.target.id}`) link.setAttribute("aria-current", "step");
          else link.removeAttribute("aria-current");
        });
      }, { rootMargin: "-18% 0px -72% 0px", threshold: 0 });
      runbookSteps.forEach((step) => observer.observe(step));
    }

    update();
  })();
</script>
